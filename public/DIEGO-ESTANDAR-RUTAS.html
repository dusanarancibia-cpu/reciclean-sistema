★TL;DR — 5 puntos clave

  1. El estándar 2025-2026 no es Distance Matrix sino Google Routes API v2 con computeRoutes + optimizeWaypointOrder=true. Soporta hasta 25 paradas con place IDs o 98 con coordenadas. Diego v8 hoy sólo hace tiempo punto-a-punto — brecha crítica.
  2. El benchmark son Routific, Onfleet y Circuit for Teams. No para competir con ellos sino para igualar sus capacidades. El estándar es: dispatcher escribe en lenguaje natural → bot extrae direcciones, valida, optimiza, devuelve secuencia + ETA + share-link.
  3. Validar direcciones es obligatorio en Chile. Numeración no oficial, comunas homónimas, calles repetidas. Google Address Validation API soporta Chile desde 2024. Diego v8 confía en lo tipeado → riesgo de despachar camión a dirección inexistente.
  4. Restricción vehicular Santiago 2026 obliga filtrado por patente. Período 4-may → 31-ago, lun-vie 07:30-21:00. Camiones sin sello verde restringidos por dígito + prohibidos dentro de Vespucio. Multa ~$100.000 CLP por incidente.
  5. Patrón arquitectónico: diego-chat-process orquesta tool calls a google-maps-distance (ya activa) + route-optimize (nueva) + verify-address (nueva). Cache en panel.maps_cache con TTL diferenciado. Costo: $0 USD/mes dentro de free tier.

1Cálculo de ruta multi-parada (TSP/VRP)

La confusión más común — y la que tiene atrapada a Diego v8 — es pensar que Distance Matrix y Route Optimization son lo mismo. No lo son.

Comparativa técnica

Aspecto Distance Matrix (legacy) computeRoutes + optimizeWaypointOrder Route Optimization API (VRP)
Algoritmo No optimiza, sólo par a par TSP simple VRP / CVRPTW
Límite paradas 25 × 25 25 con place IDs, 98 con lat/lng Miles en una request
Capacidad camión No No Sí
Ventanas horarias No No Sí
Múltiples vehículos No No Sí
Billing $5/1000 (Essentials) Compute Routes Pro (mayor) Enterprise (1.000/mes free)

Veredicto para Diego v9 Hoy Reciclean opera 1 camión por sucursal. El estándar correcto es computeRoutes con optimizeWaypointOrder=true. Migrar a Route Optimization API (VRP) es sobre-ingeniería hasta que aparezca el 3er camión simultáneo.

3Verificación coherencia de direcciones

Las direcciones tipeadas tienen 3 patologías: numeración inexistente, comuna ambigua, calles homónimas. Mandar camión a dirección no validada = combustible perdido + cliente cabreado.

Niveles de precisión Google Geocoding

Costo estimado validaciones/mes Reciclean

Reglas de aceptación

location_typeSignificadoAcción Diego
ROOFTOPExacto, coordenada del techoAceptar automático
RANGE_INTERPOLATEDInterpolada entre 2 puntosAceptar con warning
GEOMETRIC_CENTERCentro calle, sin númeroPedir confirmación
APPROXIMATESólo comuna o regiónRechazar, pedir más datos
ZERO_RESULTSDirección no existeRechazar, pedir corrección

Detección de duplicados

Antes de aceptar dirección nueva, query PostGIS contra base de clientes existentes:

SELECT id, nombre, similarity(nombre, $1) AS sim
FROM curated.clientes
WHERE ST_DWithin(
  geog_punto,
  ST_MakePoint($lng, $lat)::geography,
  50  -- metros
)
AND id != COALESCE($cliente_excluir, '00000000-0000-0000-0000-000000000000')
ORDER BY sim DESC LIMIT 5;

Si hay match a < 50m con similitud de nombre > 0.8 → alertar al dispatcher antes de crear duplicado.

Modelos de tráfico disponibles

ModeloComportamientoCuándo usar en Reciclean
BEST_GUESSHistórico + liveDefault todas las rutas
PESSIMISTICDías malosLluvia + viernes tarde + multas por atraso

Restricción crítica del API trafficModel solo funciona con routingPreference: TRAFFIC_AWARE_OPTIMAL, que es incompatible con optimizeWaypointOrder: true. Solución: 2 calls — primero optimizar con TRAFFIC_AWARE, luego pedir ETAs con TRAFFIC_AWARE_OPTIMAL + PESSIMISTIC sobre el orden ya fijado.

Restricción vehicular 2026 — función Postgres

CREATE FUNCTION panel.camion_puede_circular(
  p_patente TEXT,
  p_fecha   DATE,
  p_dentro_anillo BOOLEAN DEFAULT FALSE
) RETURNS BOOLEAN AS $$
DECLARE
  v_sello_verde BOOLEAN;
  v_ultimo INT;
  v_restringidos INT[];
BEGIN
  IF p_fecha NOT BETWEEN '2026-05-04' AND '2026-08-31'
  THEN RETURN TRUE; END IF;

  SELECT tiene_sello_verde, ultimo_digito::INT
    INTO v_sello_verde, v_ultimo
  FROM panel.flota_vehiculos WHERE patente = p_patente;

  IF v_sello_verde THEN RETURN TRUE; END IF;
  IF p_dentro_anillo THEN RETURN FALSE; END IF;

  SELECT digitos_restringidos INTO v_restringidos
  FROM panel.restriccion_vehicular_calendario
  WHERE fecha = p_fecha;

  RETURN NOT (v_ultimo = ANY(v_restringidos));
END;
$$ LANGUAGE plpgsql STABLE;

      "patente_camion": { "type": "string" },
      "modelo_trafico": {
        "type": "string",
        "enum": ["best_guess", "pessimistic", "optimistic"]
      }
    }
  }
}

Flow interno (12 pasos)

  1. Recibir tool_use de Claude con params.
  2. Validar required fields.
  3. Para cada parada: validar dirección (call interno a verify-address).
  4. Si patente_camion provista: llamar panel.camion_puede_circular().
  5. Llamar EF route-optimize con body normalizado.
  6. route-optimize chequea cache → llama Google Routes API si miss.
  7. Recibir optimizedIntermediateWaypointIndex + duration + legs.
  8. Reordenar paradas según índice optimizado.
  9. Calcular ETA por parada (acumular legs[].duration + duracion_minutos).
  10. Validar ventanas horarias contra ETAs → flagear violaciones.
  11. Generar share-link Google Maps.
  12. Devolver respuesta estructurada a Claude.

  "input_schema": {
    "type": "object",
    "required": ["direccion"],
    "properties": {
      "direccion":            { "type": "string" },
      "pais":                 { "type": "string", "default": "CL" },
      "buscar_duplicados":    { "type": "boolean", "default": true },
      "cliente_id_excluir":   { "type": "string" }
    }
  }
}

Flow interno

  1. Normalizar input (trim, agregar ", Chile" si falta).
  2. Cache check en panel.maps_cache (cache_type='geocode', TTL 180d).
  3. Llamar Google Geocoding API con components=country:CL.
  4. Evaluar location_type según tabla de reglas.
  5. (Opcional) Address Validation API para validación dura.
  6. Si buscar_duplicados=true → query PostGIS < 50m + similarity nombre.
  7. Persistir en cache.
  8. Devolver respuesta estructurada (valid, lat/lng, componentes, duplicados, alertas).
